# Claude Code

Postrun records Claude Code through two local channels: Claude Code's own OpenTelemetry export, sent to a receiver on `127.0.0.1:4318`, and a hook script that Claude Code runs on each session event. `postrun setup` turns both on, and Postrun's background process records from then on.

## Set it up

```bash
postrun setup
```

This merges Postrun's settings into `~/.claude/settings.json`, copies the hook script to `~/.postrun/bin/capture-hook.sh`, and starts recording. Run it again whenever you like: it only changes what is missing or out of date.

Then restart any Claude Code session that is already running. Claude Code reads `settings.json` only at launch, so a session started before the change keeps its old settings: it is still recorded from its hooks, but without cost and token counts.

### What the setup writes

The setup adds these keys under `env`:

| Variable | Value |
| --- | --- |
| `CLAUDE_CODE_ENABLE_TELEMETRY` | `1` |
| `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA` | `1` |
| `OTEL_LOGS_EXPORTER` | `otlp` |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/json` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://127.0.0.1:4318`, or the free port setup picked if 4318 was taken |
| `OTEL_EXPORTER_OTLP_HEADERS` | `x-postrun-key=<key>`: the telemetry key, so only Claude Code can write telemetry to Postrun. Postrun adds it to older setups when it starts. |
| `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_ASSISTANT_RESPONSES`, `OTEL_LOG_TOOL_DETAILS`, `OTEL_LOG_TOOL_CONTENT` | `1` |
| `OTEL_LOGS_EXPORT_INTERVAL` | `2000` |
| `POSTRUN_CAPTURE_DIR` | The capture folder, `~/.postrun/captures` by default |

Postrun reads only telemetry logs, so it does not ask Claude Code for metrics or traces. If an earlier setup added the metrics and traces exporters pointing at Postrun's receiver, the setup removes them; the same settings pointing anywhere else are yours and are left alone.

It also adds one hook, with a 10 second timeout, for each of these events: `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `PostToolUseFailure`, `Stop` and `SessionEnd`. The hook runs `~/.postrun/bin/capture-hook.sh`, a copy setup keeps current, so updating or moving Postrun never breaks it.

### If you already send telemetry elsewhere

If your settings already set `OTEL_EXPORTER_OTLP_ENDPOINT` (or a logs endpoint or exporter) to something that is not Postrun, setup does not replace it. It adds only the hooks and `POSTRUN_CAPTURE_DIR`, and records from hooks only. Every prompt, command, edit, read and final reply is still recorded; cost, token counts and permission decisions are not, and `postrun doctor` says so.

### How the merge behaves

- **Backup first, once.** Before the first change, the file is copied to `~/.claude/settings.json.postrun-backup`. Later runs never overwrite that backup, so it stays your true original.
- **Nothing else is touched.** Every other top-level key, env var, hook group and matcher is carried over unchanged.
- **Safe to repeat.** Postrun recognises its own hooks by their command path and updates them in place, so running setup again never adds duplicates. If it finds more than one Postrun hook for an event, it keeps one and removes the rest.
- **Changed values are reported.** If a Postrun env key already holds a different value, it is replaced and the old value is printed.
- **Atomic write.** The file is written to a temporary file and renamed, keeping its permissions. The hook script is made executable.
- **Invalid JSON stops it.** If `settings.json` is not valid JSON, nothing is written and the error names the file. Fix it by hand and run the command again.
- **A retired setting is cleaned up.** Earlier versions set `OTEL_LOG_RAW_API_BODIES`, which made Claude Code write every raw API request to disk. If its value points inside `~/.postrun`, setup removes it. Postrun never read those files; delete that directory yourself if you want.

To use a settings file other than `~/.claude/settings.json`, set `POSTRUN_CLAUDE_SETTINGS`.

<Callout type="tip" title="Undoing the setup">
  `postrun uninstall` removes Postrun's hooks and the settings it added, and leaves everything else in `settings.json`, including changes you made since, exactly as it is. A setting you already had before Postrun, with the same value, is kept. Your original file also stays in `~/.claude/settings.json.postrun-backup`.
</Callout>

## Record sessions

Postrun's background process (`postrun start`, started by setup and at login) does the recording. It:

- Runs the OTLP receiver on `127.0.0.1:4318`, which writes each session's telemetry to `sessions/<id>/otlp-logs.ndjson` in the capture folder.
- Collects hook events from `spool/`, where the hook script writes each event to its own file (under a temporary name, then renamed, so two large events written at the same moment never mix), and moves each one into `sessions/<id>/hooks.ndjson`, oldest first. It also drains `hooks.ndjson`, where hook scripts from before version 0.2 append. It reads only what is new each second, so the cost does not grow with history.
- Watches Cline sessions too. See [Cline](/capture/cline/).

When a session reaches `Stop` (the end of an assistant turn) or `SessionEnd`, the watcher waits at least 4 seconds so the last telemetry export can arrive, then builds the session from its own folder and writes what changed to the store. A session therefore appears in the review app while it is still open, with no end time, and is updated as it runs. A very long session is refreshed less often, so it never costs more than about 1% of a CPU core.

On start, the watcher catches up on every session not yet complete in the store, so sessions that ran while it was stopped are recovered. A session's folder is removed 24 hours after the session goes quiet, once it is safely in the store; set `POSTRUN_KEEP_CAPTURES=1` to keep the folders.

## Sessions recorded while Postrun was stopped

Claude Code's hooks save events to `~/.postrun/captures/spool` whether Postrun is running or not. When Postrun starts, it catches up on every session it missed. They are built from the hooks alone, so they have no cost or token counts, and the review app says so.

Pausing recording in Settings is different: while paused, the hook drops events and the receiver drops telemetry, so nothing from that time is recorded. Starting or restarting Postrun resumes.

## How a session is built

The Claude Code adapter reads a session's `otlp-logs.ndjson` and `hooks.ndjson` and joins them by `tool_use_id` and prompt id.

- **The hook is the content source.** It carries the full tool input, the full command output and the full prompt text.
- **Telemetry is for ordering and cost.** The OTLP log export supplies the event order, the correlation ids, cost and token counts. Its copy of tool input is truncated, so Postrun never uses it as content.

| Telemetry event | Hook record | Step |
| --- | --- | --- |
| `tool_result` for Bash | `PostToolUse` or `PostToolUseFailure` | `command` |
| `tool_result` for Edit or Write | `PostToolUse` | `edit` |
| `tool_result` for Read | `PostToolUse` | `read` |
| `tool_result` for any other tool | `PostToolUse` or `PostToolUseFailure` | `other`, with the full tool name |
| `user_prompt` | `UserPromptSubmit` | `message` with role `user` |
| `assistant_response` on the main thread | `Stop` (final response of the turn) | `message` with role `assistant` |
| `assistant_response` side calls, such as title generation | none | `other` |

Other telemetry events, such as `api_request` and `tool_decision`, are not steps. `api_request` feeds the session's cost and token totals. `tool_decision` sets each step's `decision`: an accept that came from your configuration is `auto`, an accept you made is `accepted`. A step's `outcome` comes from `PostToolUseFailure` or the telemetry success flag.

A step with no matching hook record has no inline content. It is stored with `content_status: "reference_only"` and a pointer in `output_ref` or `text_ref`, and the review app marks it as reference-only. Assistant prose between tool calls is often reference-only for this reason, because only the final response of a turn reaches the `Stop` hook.

Command output is capped at 30,000 characters. Exit codes are usually present only on failure, parsed from the failure text.

## Change the port

If port 4318 is taken by another program (often an OpenTelemetry collector), `postrun setup` picks the next free port, writes it into `settings.json`, and remembers it in `~/.postrun/config.json`. Restart Claude Code afterwards so it sends to the new port. Other paths can be changed with the [environment variables](/reference/cli/#environment-variables), which you should not normally need.

## What Postrun does not do

- It never asks Claude Code to dump raw API request bodies to disk.
- It never writes to Claude Code's own files other than `settings.json`.
- The capture files can still hold anything a session printed, including the output of a command like `env`. Treat `~/.postrun` as sensitive. See the [security model](/security/).
